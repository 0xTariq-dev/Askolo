---
name: Space-centric product scope
description: Askolo product UI uses Spaces for family and professional contexts, with Home and explicit Agent scope.
---

Askolo is not limited to families or households. A Space can represent a family or a professional team; Spaces and invitations are cornerstones of the product. Use “Space” in product-facing language. The current technical schema and API use workspace-scoped identifiers; do not silently rename that contract.

Home is a concise, factual view of the current day only, not a plot of every item or an AI-written narrative by default. Show up to three user-selected or suggested focus actions from that day's Plan. The Email summary counts unread messages and action-needed messages (awaiting the user's reply or flagged/starred), without listing individual emails. The Calendar summary shows the day's event count and next event/time, counting multi-day events on each day they overlap. The inline Home Agent entry opens the same full Agent, not a day-limited assistant; it may start with day context but retains the Agent's broader context within the active Space or All Spaces scope and normal authorization/privacy boundaries. Other dates are available in Agenda. All Spaces is a selection in the existing Space dropdown, not a separate view or sidebar tab; it aggregates Tasks/Plan items, Calendar events, and email summary counts, labeled by Space. Agenda is the chosen broader name and combines planning items and Calendar events in one calendar object based on ReUI's `c-event-calendar-1`, preserving existing Month/Week/Day views, date navigation, Today behavior, Google Calendar sync, and event management. Today returns to the current date in Day view; the element's view dropdown changes views. All exposed settings controls work, and the new-event button opens a modal for supported event and task types. The Plan's time zone defaults from the creator's device when created; each member can override their own display time zone in Settings, so shared-Space members see their own effective local dates and times. Home layout references are examples, not fixed templates: each user can customize their layout independently for each Space. Reuse existing design-system support for card resizing and drag-and-drop ordering; predefined widgets are future scope. At the end of a Plan day, carry unfinished items with no due date forward automatically; ask individually before carrying forward an unfinished item with a due date.

**Why:** the user confirmed the full Agent scope, current-day-only Home, All Spaces dropdown contents, Agenda name, combined ReUI calendar object and controls, action-needed criteria, focus-action behavior, and per-viewer time-zone display. They also specified minimal provider-data mapping, per-Space layout, and carry-forward rules.

**How to apply:** use Space and Home in user-facing copy, support family and professional team contexts, represent All Spaces in the Space dropdown, label aggregated items with their Space, keep Agent actions bounded to the selected scope without limiting Agent context to the current day, keep Home on today and use Agenda for other dates, combine Plan items and events in the full Calendar object with working controls and creation flows, apply each viewer's effective time zone without changing other members' display, scope Home layout preferences to the user-Space pair, count calendar events on each selected day they overlap, auto-carry forward undated unfinished items, and require individual approval before carrying forward items with a due date. Preserve existing technical workspace identifiers unless a separate contract change is approved.
