---
name: Space-centric product scope
description: Askolo product UI uses Spaces for family and professional contexts, with Home and explicit Agent scope.
---

Askolo is not limited to families or households. A Space can represent a family or a professional team; Spaces and invitations are cornerstones of the product. Use “Space” in product-facing language. The current technical schema and API use workspace-scoped identifiers; do not silently rename that contract.

The main view is named Home and presents a concise, factual roll-up for the selected Space rather than plotting every task, event, email, and Plan entry. Its first additional cards are an Email summary and a Calendar summary; keep them concise, and leave their exact metrics and contents open. Focus actions come from items already in the day's Plan. It is not an AI-generated narrative by default. Home has an inline, day-aware Agent entry alongside the separate full Agent page. Provide a separate All Spaces view and label each item with its Space. The Agent follows the selected Space or All Spaces scope the user is using and never silently widens it. Home layout references are examples, not fixed templates: each user can customize their layout independently for each Space. Reuse existing design-system support for card resizing and drag-and-drop ordering; predefined widgets are future scope. At the end of a Plan day, carry unfinished items with no due date forward automatically; ask individually before carrying forward an unfinished item with a due date.

**Why:** the user explicitly defined the initial Home summary cards, inline Agent entry, All Spaces, Agent-scope, per-user/per-Space layout, and separate carry-forward rules for dated and undated unfinished Plan items. They supplied a sample layout but said it should not be followed strictly, and deferred predefined widgets.

**How to apply:** use Space and Home in user-facing navigation and copy, support family and professional team contexts, label cross-Space items, keep Agent actions bounded to the user's explicit scope, render the contextual Agent inline while keeping the full Agent page separate, scope layout preferences to the user-Space pair, auto-carry forward undated unfinished items, and require individual approval before carrying forward items with a due date. Preserve existing technical workspace identifiers unless a separate contract change is approved.
