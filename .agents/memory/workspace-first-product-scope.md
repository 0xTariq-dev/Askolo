---
name: Space-centric product scope
description: Askolo product UI uses Spaces for family and professional contexts, with Home and explicit Agent scope.
---

Askolo is not limited to families or households. A Space can represent a family or a professional team; Spaces and invitations are cornerstones of the product. Use “Space” in product-facing language. The current technical schema and API use workspace-scoped identifiers; do not silently rename that contract.

Home is a concise, factual daily roll-up for the selected Space, not a plot of every item or an AI-written narrative by default. Its initial Email summary shows unread and action-needed counts without individual emails; its Calendar summary shows the selected day's event count and next event/time, counting multi-day events on each day they overlap. Focus actions come from that day's Plan. The inline Home Agent entry opens the same full Agent, not a day-limited assistant; it may start with day context but retains the Agent's broader context within the active Space or All Spaces scope and normal authorization/privacy boundaries. All Spaces is a selection in the existing Space dropdown, not a separate view or sidebar tab; aggregated items retain their Space labels. The combined planning/Calendar surface preserves the full existing Calendar; “Agenda” is a proposed broader product label, while final naming and placement of the full Calendar relative to the daily Plan remain open. Within daily planning, preserve the order of user-chosen focus actions, chronologically scheduled events/timed tasks, then flexible tasks and habits. Home layout references are examples, not fixed templates: each user can customize their layout independently for each Space. Reuse existing design-system support for card resizing and drag-and-drop ordering; predefined widgets are future scope. At the end of a Plan day, carry unfinished items with no due date forward automatically; ask individually before carrying forward an unfinished item with a due date.

**Why:** the user clarified that Home is a quick entry to the full Agent, All Spaces is a Space-dropdown scope, and the planning surface retains the full Calendar; they also specified minimal provider-data caching for responsive plotting. The user defined the initial Home summaries, multi-day event handling, per-Space layout, and separate carry-forward rules, while leaving the broader surface name/order open.

**How to apply:** use Space and Home in user-facing copy, support family and professional team contexts, represent All Spaces in the Space dropdown, label aggregated items with their Space, keep Agent actions bounded to the selected scope without limiting Agent context to the current day, preserve the full Calendar in the combined planning surface, retain the agreed within-day Plan ordering while leaving its placement relative to the full Calendar open, scope Home layout preferences to the user-Space pair, count calendar events on each selected day they overlap, auto-carry forward undated unfinished items, and require individual approval before carrying forward items with a due date. Preserve existing technical workspace identifiers unless a separate contract change is approved.
